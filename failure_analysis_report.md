# Top 5 Failure Analysis — AmazonHelp AI Support Agent

## 1. Intent ambiguity
**Example:** A real customer message from the Golden Evaluation Set is included in `top_5_failure_analysis.csv`.

**Hypothesis:** TF-IDF relies on word overlap. Order-status and delivery-problem messages naturally share words such as order, package, delivery, late, and arrive.

**Next improvement:** Add more independently hand-labelled examples, use semantic embeddings, include conversation context, and calibrate confidence.

## 2. Unnecessary escalation from low confidence
**Observed result:** The current escalation policy achieved 100% recall for escalation but only 22% precision.

**Hypothesis:** The 0.55 confidence threshold is conservative and is being applied before the classifier is properly calibrated.

**Next improvement:** Tune the threshold on a separate validation set and measure automation coverage versus unsafe automation.

## 3. Lexical retrieval mismatch
**Hypothesis:** TF-IDF can retrieve conversations with similar words but a different underlying problem or resolution.

**Next improvement:** Use sentence embeddings + intent-aware filtering + reranking.

## 4. Reply is only partially grounded
**Hypothesis:** The current reply generator uses conservative intent templates. It is safe, but it does not fully exploit the retrieved historical replies.

**Next improvement:** Give an LLM the customer message, intent, and top retrieved historical examples and require it to ground every factual claim in that evidence.

## 5. Evaluation leakage / misleading baseline
**Observed result:** The keyword baseline scored 100%.

**Why misleading:** The keyword rules were also used to create the initial labels. Therefore, the baseline is effectively being evaluated against labels generated by the same rules.

**Next improvement:** Independently hand-label the final 150–250 examples and then evaluate all baselines against those labels.
